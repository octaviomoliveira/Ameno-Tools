# ADR 0005 — Max 2026 primeiro

- Estado: aceita
- Data: 2026-09-03

## Contexto

O desenvolvimento e a necessidade imediata estão no 3ds Max 2026. Embora versões desde o 2021 sejam desejáveis no futuro, impor agora a interseção de seis APIs aumentaria testes, adapters e restrições antes de existir um MVP validado. A API de menus, por exemplo, mudou significativamente no Max 2025.

## Decisão

Construir e validar primeiro a melhor versão possível do Ameno Dimensions no 3ds Max 2026.

- o MVP suporta oficialmente apenas o Max 2026;
- a UX e os recursos não serão reduzidos apenas para preservar compatibilidade hipotética;
- domínio, persistência e representação continuam desacoplados das integrações do host;
- chamadas do Max ficam concentradas em serviços, evitando acoplamento gratuito;
- adapters de versões antigas serão criados somente depois de inventário e teste reais;
- a ordem de portabilidade será decidida por demanda e custo, não pela numeração desejada.

## Consequências

### Positivas

- entrega mais rápida para o problema atual;
- liberdade para explorar corretamente o Max 2026;
- matriz de testes inicial pequena;
- a versão estável do 2026 vira referência para avaliar qualquer port futuro.

### Custos

- Max 2021–2025 não serão anunciados como suportados no MVP;
- alguns recursos podem exigir fallback ou UI diferente numa futura portabilidade;
- a expansão poderá precisar de dois caminhos de menu, por causa da mudança no Max 2025.

## Regra de portabilidade

Nenhuma abstração será criada só porque uma API talvez seja diferente. A abstração nasce quando uma incompatibilidade comprovada exigir duas implementações. Ao mesmo tempo, dados de cena e regras de cálculo não devem depender diretamente de widgets, menus ou APIs exclusivas do host.
